## Architecture — current state

**Distribution changed.** The app now ships through **Google Play internal
testing** as `io.github.pr0zak.pitstop`, not as a sideloaded APK.
`com.pitstop` was rejected — Play reserves a package name permanently once
claimed, even by an unpublished draft, so a 404 on the public listing proves
nothing. The `namespace` deliberately stays `com.pitstop`; Android has never
required the two to match.

**Android Auto works, and only because Play installs it.** AA lists only
Play-installed apps. A sideloaded build declares an identical `CarAppService`,
registers identically, and is filtered out with no error and no entry. Proven
by controlled A/B on one device: two installs, same code, only
`installerPackageName` differing, AA listed exactly one. The Settings →
Android Auto header now surfaces this as a status pill.

**The car surface is quota-governed.** The host allows five templates per task
and then *closes the app*. An update only avoids the quota if it is a
*refresh*, which requires unchanged item/row **titles** — so live values live
in `setText()`/`addText()`, never in a title. Everything else about the car UI
follows from that one rule.

**Hybrid capture (ADR-019)** and the **hybrid fuel-level estimator** are
unchanged. The phone now polls 24 PIDs (was 15), so the Live screen fills in
on BLE-only drives.

## Recently closed (2026-08-07 session, v0.1.212 → v0.1.227)

**Play Store distribution stood up from nothing.** Release signing wired
(upload key at `~/.pitstop-keys/`, outside the repo); self-updater removed
(`REQUEST_INSTALL_PACKAGES` + FileProvider + the two GitHub-APK links Play's
Device and Network Abuse policy forbids); `applicationId` moved to
`io.github.pr0zak.pitstop`; native debug symbols enabled.

**R8 had never been run.** `isMinifyEnabled = true` was set long ago but
`bundleRelease` had never executed, so minification was entirely unproven.
Two real defects, both release-only:
- **jctools** field names renamed → `NoSuchFieldException: consumerIndex` →
  `ExceptionInInitializerError` on **every MQTT connect**, an unrecoverable
  crash loop. `-keep class io.netty.**` looked like it covered this; hivemq
  also depends on the *unshaded* `org.jctools` artifact, which is the one that
  got obfuscated.
- **Exception class names** renamed → crash reports shipped `type="o"`.
  `-keepnames class * extends java.lang.Throwable`.

**Android Auto brought up from zero.** Four runtime defects, none visible to
inspection: `GridItem` requires an image; `ActionStrip` allows one titled
action; live values in a title burn the template quota until the host closes
the app; an empty `Badge` throws. TabTemplate with a configurable 4-tab set,
per-tab tile pickers, per-metric glyphs.

**Phone Live screen completed.** Nine PIDs added (0x9E exhaust, 0x3C/0x3D
catalyst, 0x24 O2 λ, 0x44 cmd AFR, 0x23 fuel rail, 0x2C EGR, 0x2E evap, 0x68
intake) plus Run time. `maf_sensor_a` → `maf_air_flow`: the same sensor had
two names depending on whether it arrived over BLE or WiFi.

**Web + phone.** Odometer charted (offset-corrected server-side so it matches
the dash), trip-chart metrics, `UnitFormat.Quantity` unit refactor, linear
fuel-level bar replacing a semicircle with four independent geometry faults,
and the launcher icon/favicon regenerated from one construction rule after the
arcs were found to be drawn around three different centres.
