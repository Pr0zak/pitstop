## Recently closed (last session)

- **HTTP timeout for drive uploads (2026-05-14, v0.1.129)** — `AppModule`'s OkHttp client had `readTimeout(20s)` + default `writeTimeout(10s)`, which tripped on multi-MB drive payloads (20k–25k frames). The server completed the upload but the response didn't get back in time; client logged "network/server error, stopping pass" and the user saw "Sync failed" / partial drains. The retry came back as `duplicate=true` instantly, proving the prior attempt had landed. Bumped both to 60 s. User-facing symptom: drives no longer need 2–3 taps of Sync now to clear the queue.
- **SETTINGS-1 — Collapsible Settings sections (2026-05-14, v0.1.128)** — `SettingsSection` gained `collapsible` + `initiallyExpanded` params with a tap-to-expand chevron, expanded state in `rememberSaveable(title)`. ConfigScreen reordered so daily-use sections (Bridge service, OBD device, MQTT broker, Connectivity) sit at top expanded, cold-config (Pitstop server, Vehicle, Display, Logs) collapses by default, App (version + check-for-updates) anchors the bottom.
- **CI-1 — Node 24 actions bump (2026-05-14)** — every workflow action that emitted a deprecation warning is now pinned to a Node-24 major: `actions/checkout@v6`, `actions/setup-java@v5`, `android-actions/setup-android@v4`, `gradle/actions/setup-gradle@v5` (NOT v6 — caching component split out into a commercial library there), `softprops/action-gh-release@v3`, `docker/setup-buildx-action@v4`, `docker/login-action@v4`, `docker/metadata-action@v6`, `docker/build-push-action@v7`. v0.1.128 was the first fully warning-free build.
- **Icon optical centering (2026-05-14, v0.1.127)** — both adaptive-icon foregrounds (launcher + Add-Fillup shortcut) had under-corrected optical upward shifts: 1.18 dp and 2.2 dp respectively, leaving black-mask gap visible above the dial on Pixel-launcher circular masks. Bumped to 4.18 dp and 5.2 dp (translateY 13.0→10.0 and 7.0→4.0). Both still fit inside the 36 dp mask radius and the 21–87 dp safe zone.
- **Manual-sync toggle save-race (2026-05-14, v0.1.126)** — user flipped the Settings switch but didn't tap Save, so DataStore stayed `false` and drives kept auto-uploading after each seal. Shipped a focused `SettingsRepository.setManualSyncOnly(value)` setter wired through `ConfigViewModel.setManualSyncOnly`; toggle now auto-persists.
- **Sync-now silent UX (2026-05-14, v0.1.126)** — History `Sync now` chip used to call `DriveSealer.kickWorker(force=true)` on a detached scope with zero UI feedback. `HistoryViewModel.syncNow` now runs `DriveUploader.drain` on `viewModelScope`, exposing a `SyncState` flow (Idle / InProgress / Done(uploaded, remaining) / Failed) that the chip + status line consume.
- **BLE auth flap (2026-05-14)** — phone hit GATT status 5 (`INSUFFICIENT_AUTHENTICATION`) on every connect attempt to the WiCAN; resolved by Phone Settings → Bluetooth → forget the device + re-pair. Not a code bug; the bond on one side had been cleared. No follow-up task — the BLE-lost watchdog (ADR-017) already covers the trip-splitting side of this.
- **VERIFY-1/v0.1.123** — phone APK installed; the phone is currently running v0.1.125 build 227 per uploaded `client_logs`, so this task is implicitly superseded.
- **VERIFY-2/v0.1.123** — `intake_air_temp` shows plausible values via the WiCAN custom-PID workaround; broker tail captured a `wican/pilot19/pid` retained message with `intake_air_temp: 33` (~91 °F idle/cooled), well clear of the broken-bitmap –39 °C value.
